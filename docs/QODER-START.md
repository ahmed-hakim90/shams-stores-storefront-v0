# بداية جاهزة لـ Qoder وأي موديل آخر

افتح مستودع `shams-stores-storefront-v0` نفسه. ألصق النص التالي في بداية المهمة أو أرفق الملفات المذكورة صراحة. لا نفترض أن Qoder يقرأ هذا الملف تلقائيًا، ولا نحتاج تعديل `.qoder/settings.local.json` أو الملفات المحلية المتجاهلة.

## النص الجاهز

```text
أنت تعمل على Shams Stores headless storefront.
اقرأ أولًا AGENTS.md ثم docs/QODER-HANDOFF-2026-09-19.md،
وdocs/QODER-ISSUES.md وdocs/QODER-PLUGIN-GUIDE.md ثم docs/API-INTEGRATION.md
وdocs/DEVELOPMENT-RUNBOOK.md وdocs/PAYMOB-VERCEL.md، ثم التقرير الحالي المرتبط بها.

قبل التعديل افحص git status وgit diff للملفات ذات الصلة. توجد تعديلات
سابقة غير ملتزم بها؛ حافظ عليها ولا تعمل reset أو تنظيفًا شاملًا.
فرّق بين ما نُفّذ في الكود، وما اختُبر تاريخيًا، وما نُشر فعلًا.
ملفات PROJECT_HANDOFF وCOMMERCE_IMPLEMENTATION القديمة ليست وحدها مرجع الحالة.

قرارات ثابتة: الهاتف إجباري؛ نقص الحقول يظهر validation عند التأكيد
ولا يعطل الزر مقدمًا. احتفظ بمنع إرسال الطلب المكرر وحماية النتيجة غير المؤكدة.
الضمان والوكيل والتوافق من API؛ لا تخترع بيانات تجارية أو سياسات.
إعدادات حقول WordPress ليست موروثة تلقائيًا بعد: لا تدّعِ اكتمالها.
حافظ على الشعار وألوان وتوكنز البراند والتعديلات القائمة.

مصدر Commerce UX في مستودع WordPress المنفصل؛ Shams Headless في
wordpress-plugin/shams-headless داخل هذا المستودع. لا تخلط ملكية البلاجنين.
المفضلة تتطلب 1.1.1 أو أحدث، والدفع الجديد يتطلب Shams Headless 1.2.1؛
Paymob داخل الموقع عبر Pixel مع فصل Test/Live، ولا hosted redirect افتراضي؛
لا تدمج مخازن المفضلة ولا تفعّل بلاجن ولا تنشر ولا تنشئ طلبات دون تصريح.
لا تعرض الأسرار أو محتويات env أو إعدادات Qoder الخاصة.

نفّذ المهمة المحددة أدناه فقط، باستخدام الأنماط الموجودة واختبارات مناسبة.
حدّث التوثيق عند تغيير السلوك/العقد. اختم بالمُنفّذ، والفحوص الفعلية، والمتبقي.
رد بالمصري باختصار. هذه التعليمات ليست إذنًا بالنشر أو الدفع أو تغييرات الإنتاج.

المهمة المطلوبة الآن: [اكتب المهمة وحدودها هنا]
```
