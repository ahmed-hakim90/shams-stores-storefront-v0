# تنفيذ ربط Shams API — 19 سبتمبر 2026

## ما تم تنفيذه

- طبقة خادم للـ content API الجديد، وطلبات مجمعة بحد 20 منتجًا، وتوحيد الطلب المتزامن لنفس المسار. الاستجابات الجديدة لا تستخدم cache أسعار، ولا تغيّر سعر/مخزون Store API.
- ضمان ووكيل من `assurances` في الكروت وصفحة المنتج؛ إخفاء الشارات غير المفعلة وعدم اختراع مدة ضمان أو اسم وكيل.
- قسم الإكسسوارات من المحرك الحقيقي مع exact/compatible/recommended والملاحظة. خيارات العدسات والكِت، حقول اتخاذ القرار، روابط الدليل/الفيرموير، وSEO overrides.
- بيانات الفروع والتليفونات من shell، وقوائم الفوتر عند ضبط مواضع shams-footer-help/shams-footer-policies. التنقل الأساسي يحتفظ بترتيب الكتالوج الحالي؛ لم ننقل قوائم قالب Electro كلها عشوائيًا.
- هيرو الحملات من API، تحكم يدوي قابل للوحة المفاتيح، صورة desktop/mobile، وخلفية بديلة عند فشل الصورة. عند غياب المحتوى يستخدم هيرو فئات محليًا دون ربط صورة فئة بمنتج عشوائي.
- دعم shoppable hero كصورة مع قائمة منتجات قابلة للشراء؛ مواضع hotspots التفاعلية الدقيقة ليست منفذة في هذه النسخة.
- صور taxonomy مدمجة مع التصنيفات الحالية دون استبدال counts أو ترتيب الكتالوج.
- جلب صفحات المحتوى بالـ slug ثم ID وعرض HTML بعد تنظيفه، ودمج SEO overrides. السياسات غير المتاحة تظهر رسالة واضحة بدل وعود محلية غير موثقة.
- فصل endpoint مفضلة العميل في Shams Headless 1.1.1 إلى `/shams/v1/customer/wishlist`. نفس Bearer authentication ونفس بيانات `shams_wishlist`؛ لا حذف أو دمج تلقائي لمفضلة Commerce UX. aliases القديمة فقط عند غياب مالك Commerce UX. أخطاء القراءة لم تعد تُعرض كقائمة فارغة سليمة.
- الهاتف إجباري. زر التأكيد متاح لإظهار الحقول الناقصة ويركز أول خطأ. توقف تحديث العنوان مع كل كتابة؛ تحديث الشحن صريح. منع النقر المتكرر أثناء إرسال الطلب، وحماية النتيجة غير المؤكدة، ما زالا موجودين.
- توحيد hover الأزرار/الكروت، ظهور أدوات الكارت مع keyboard focus، علامة تنقل الموبايل، وتقليل ارتفاع معرض الموبايل مع إظهار الاسم والسعر والتوفر قبله.
- إزالة شريط الخصومات/التقسيط الثابت، شحن مجاني غير موثق، ضمان رسمي وإرجاع ثابتين، وأرقام JSON-LD الوهمية. عدم تغيير الشعار أو ألوان البراند الأساسية.
- استبدال تقييمات demo على المنتج الحي بقراءة تقييماته الفعلية. لا زر إرسال تقييم يدعي نجاحًا دون حفظ.
- إصلاح SSR لوصف المنتج: النص الآمن يظهر على الخادم، ثم DOMPurify ينسق HTML في المتصفح. لا اعتماد جديد مطلوب.

## التحقق المنفذ

- `pnpm test`: 38 اختبارًا ناجحًا، تشمل batching، اختلاف ترتيب IDs، optional API failure، عدم الاحتفاظ بسعر الاستجابة، بيانات عربية، false/null، الروابط غير الآمنة، والهاتف الإجباري.
- `pnpm typecheck`: ناجح؛ كذلك TypeScript داخل build النهائي.
- `pnpm build`: ناجح. تحذير middleware/proxy موجود سابقًا ولم نغير middleware ضمن هذا النطاق.
- PHP route fixture نجح بحضور Commerce UX وغيابه؛ فحص syntax لجميع ملفات بلاجن الإصدار الجديد: 10 ملفات ناجحة.
- API الفعلي أعاد HTTP 200 لمسارات modules/site-content/catalog terms، وكذلك content/accessories لمنتج Canon R50. ظهرت توصيات فعلية، منها adapter مع ملاحظة العدسة وذاكرات بدرجات توافق مختلفة.
- الاختبار الحي أظهر تذبذبًا لاحقًا في زمن الاستجابة (بعض الطلبات تجاوزت 15 ثانية) وصورة حملة لم تُحمّل. تم التحقق من سلوك fallback؛ الحد الاختياري داخل التطبيق 8 ثوانٍ. هذا ليس قياس أداء إنتاجي معتمدًا.
- السلة: أُضيف منتج واحد إلى جلسة الاختبار ثم أُزيل؛ تأكدت السلة الفارغة. لم يُنشأ طلب أو دفع، ولم تُدخل بيانات شخصية.
- الدفع: الضغط على التأكيد والحقول فارغة أظهر الأخطاء وركز `checkout-firstName`؛ phone يحمل required، والزر لم يكن disabled لمجرد نقص الحقول.
- العرض: 390 و768 و1024 و1440 دون overflow أفقي للشاشات المفحوصة. keyboard focus كشف أدوات الكارت ووصل opacity إلى 1. تم عرض حملتي Tamron وSony من API والتنقل بينهما، وتوثيق صورتي desktop/mobile الفعليتين.
- ملفات الأدلة تحت `docs/audit-2026-09-19/implemented/`. اللقطات توثق المنتج والتحقق من الدفع والحملات والمقاسات؛ هذه معاينة محلية وليست شهادة إطلاق.

## تشغيل الإصدار

1. التحقق من Commerce UX 0.8.0 والـ endpoints من بيئة التطبيق: `node scripts/check-shams-content.mjs`؛ السكربت لا يطبع credentials أو محتوى حسابات.
2. تحديث Shams Headless إلى ZIP 1.1.1 قبل نشر واجهة تستخدم مسار wishlist الجديد. خذ نسخة من الإصدار النشط أولًا. الحزمة مُجهزة محليًا ولم تُرفع أو تُفعل.
3. اختبر حساب عميل على staging: GET/POST/DELETE للمفضلة، auth failure، وتجربة checkout كاملة بوسائل الاختبار المعتمدة.
4. `SHAMS_CONTENT_API_ENABLED=false` يعطل الإثراء الاختياري للرجوع؛ لا يعيد مسار wishlist القديم. تراجع frontend ونسخة headless plugin معًا لو لزم rollback للمفضلة. بياناتها لا تُحذف.
5. لا تغييرات في `.env.local`، ولا commit/push/deploy، ولا تفعيل بلاجن أو تعديل إعدادات ووردبريس الحية.

## حدود النسخة وما بقي من الخطة الأصلية

هذه النسخة تنفذ الربط الأساسي وتحسينات الثقة والتفاعل والدفع؛ لا تمثل إغلاق كل بنود خطة التطوير طويلة النطاق.

- التعريب الكامل ومبدل اللغة وRTL الشامل لم تُنفذ. محتوى العربية القادم من API يعرض باتجاه تلقائي، لكن الواجهة ما زالت إنجليزية.
- إعدادات حقول checkout لا تُورث تلقائيًا من ThemeHigh/WordPress؛ الهاتف الإجباري مطابق لتأكيد المالك، ولا يوجد schema حقول في API 0.8.0. تحتاج هذه النقطة عقدًا من مالك الحقول.
- لا تفعيل لكل خيارات commerce_ui: تم استهلاك add_label؛ إعدادات العرض الأخرى ليست حجة لتطبيق CSS ووردبريس على headless.
- لا نقل لشاشات الإدارة/Orders Hub إلى العملاء، ولا استخدام `/admin/modules` في الواجهة العامة.
- لم يحدث دمج تلقائي لقوائم المفضلة المخزنة في بلاجنين؛ تم حفظ بيانات كل مالك وحسم مسار العميل بدل هجرة صامتة.
- لا اختبار حساب فعلي أو بوابة دفع/ويبهوك، ولا قياس Core Web Vitals إنتاجي، ولا اعتماد إطلاق.
- بيانات/صور API البطيئة أو غير المتاحة تحتاج إصلاحًا في المصدر لتضمن ظهور المحتوى المُدار باستمرار؛ fallback يمنع تعطيل الصفحة لكنه لا يصلح الاستضافة.
