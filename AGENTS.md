Read [docs/START-HERE.md](docs/START-HERE.md) before changing this repository. Read the linked API contract and runbook for the affected area. Qoder and other assistants can use [docs/QODER-START.md](docs/QODER-START.md) as an explicit onboarding prompt.

- Follow the owner's latest instruction; reply in concise Egyptian Arabic unless asked otherwise.
- Inspect `git status` and the relevant diff first. Uncommitted changes are existing work: never reset, overwrite, or reformat them wholesale.
- Reuse canonical components, tokens and API owners. No invented prices, warranty terms, agent identities, compatibility, policies or deployment status.
- Phone is required. Missing checkout fields should produce visible errors and focus the first error when confirmation is clicked. Preserve protection during actual submission and uncertain outcomes.
- Keep credentials server-side; never print environment files, tokens, private account data or local Qoder settings.
- No commit, push, deploy, plugin activation, production writes, orders or payment without explicit authorization. README describes automatic deployment on main merges; verify the destination before any authorized release.
- Keep mobile, keyboard access, RTL content, optional API failures and safe fallbacks in scope. Verify behavior at its boundary, not only compilation.
- Update relevant docs when contracts or behavior change. Report exactly which checks ran and which remain blocked.
